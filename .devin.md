# .devin.md — Bee Baked Bets Standard Operating Playbook

This file is the operating playbook for any agent or contributor changing the
sportsbook scrapers in this repository. It complements `.windsurfrules`; where
the two overlap, `.windsurfrules` remains authoritative on betting math,
directory layout, and secret handling.

---

## 1. Scope

Applies to every module that fetches or parses sportsbook data:

| Layer | Files |
|---|---|
| Browser scrapers | `scraper_unified.py`, `scraper_draftkings.py`, `scraper_betmgm.py`, `scraper_fanduel.py`, `scraper_oddsharvester.py` |
| Stat scrapers | `scraper_mlb_statcast_hr.py`, `scraper_pybaseball_fip.py`, `daily_stat_ingest.py` |
| API ingestion | `master_odds_fetcher.py`, `sgo_sharp_ingest.py`, `bot_propodds_nba.py`, `bot_parlay_props.py`, `supabase/functions/odds-cache-ingest/` |
| Persistence | `db_manager.py`, `services/odds_scraper_ingest.py` |

---

## 2. Procedure for updating a scraper

Follow these steps in order. Do not skip steps.

1. **Reproduce against a fixture, not the live site.** Capture a saved HTML/JSON
   payload into `tests/` and write the failing assertion first. Never begin by
   pointing the scraper at production.
2. **Confirm the break is a selector/schema change** by diffing the captured
   payload against the parser's expectations. Do not "fix" a scraper by widening
   exception handling until the root cause is identified.
3. **Change only the parsing layer.** Selector updates, field mapping, and
   normalization live in the scraper module. The output contract handed to
   `db_manager` must not change shape without a corresponding schema update in
   the `supabase_*_schema.sql` files.
4. **Preserve the throttle.** See §3. Any new request site must go through the
   shared pacing helper.
5. **Cache before you consume.** See §4. Parsed payloads are persisted first,
   then read back for scanning — never fed straight into the scanners.
6. **Add or update a unit test** under `tests/test_*.py` that runs entirely from
   the saved fixture, with no network access.
7. **Run the gates locally:**
   ```bash
   ruff check .
   python -m unittest discover -s tests -p "test_*.py"
   ```
8. **Enable behind a flag.** New scrapers ship disabled by default via an
   `ENABLE_*_SCRAPER` environment flag read through `utils.config.env_flag`, so
   a regression can be turned off without a redeploy.
9. **Open a PR.** Never push scraper changes directly to `main`. Note in the PR
   which fixture the change was validated against.

## 3. Request throttle — 30 seconds

**The scraper must maintain a minimum 30-second interval between requests to the
same upstream host.** This protects the free API tier and keeps our request
pattern away from bookmaker rate limiting.

- The 30-second floor applies per host, including retries and proxy retries.
  A retry is a request; it does not get an exemption.
- Back off, do not burst. On a 429 or 403, escalate the interval (60s, 120s)
  rather than rotating immediately to another proxy at full speed.
- Concurrency does not bypass the throttle. If requests are parallelized across
  leagues or events, the aggregate rate to a single host must still respect the
  30-second floor.
- The interval is configurable upward only. A value below 30 seconds is a
  violation of this playbook, not a tuning decision.
- Existing pacing constants (`SGO_LEAGUE_STAGGER_SECONDS`,
  `PARLAY_REQUEST_DELAY`, `SGO_GRADER_FETCH_DELAY_SECONDS`) currently default to
  1–2 seconds. Any new scraper work must not copy those values as a template;
  new request sites use the 30-second floor.
- Log the throttle wait and the remaining-quota header (`x-requests-remaining`)
  on every upstream call so budget burn is auditable from CI logs.

## 4. Caching — persist every payload before use

**All API and scraper payloads must be written to the local database cache
immediately on retrieval, before any downstream consumer reads them.**

- Writes go through `db_manager.py`. Do not open ad-hoc database connections or
  invent a parallel persistence path inside a scraper module.
- Read paths check the cache first (`get_master_cache`, `hydrate_market_cache`).
  A scanner must never trigger an upstream fetch to satisfy a read that the
  cache could have answered.
- Cache entries record a fetch timestamp. Staleness is decided by the consumer
  against that timestamp — not by re-fetching to check.
- On a failed persist, the dead-letter Discord webhook
  (`DISCORD_DEAD_LETTER_WEBHOOK_URL`) fallback must remain in the path. Do not
  remove it, and do not swallow the failure silently.
- **Note on the storage engine:** this repository's local store is Supabase
  (PostgreSQL) with a local JSON fallback (`pending_bets_log.json`,
  `hive_alert_cache.json`). There is no SQLite database in the project today.
  The rule above is written against the actual persistence layer. If a SQLite
  cache is intended as a future local-development store, it must be introduced
  deliberately behind `db_manager.py` and this section updated at that time.

## 5. Forbidden Actions

The following are prohibited without explicit, written approval from the
repository owner. There is no "small exception" to any of these.

### 5.1 Do not modify the core expected value calculator

Off-limits without approval:

- The EV formula `EV% = (true_probability * offered_decimal_odds) - 1.0`
- The de-vigging implementations (power / multiplicative / Shin) and the choice
  of power as the default
- Pinnacle as the sole sharp baseline for true probability
- The Quarter-Kelly fraction (1/4) and the bankroll cap (default 5%)
- The odds conversion helpers in `utils/odds.py` and the sizing helpers in
  `utils/model_pricing.py`

A scraper fix is never a reason to touch these files. If a scraper change
appears to require an EV-math change, stop and escalate — that signals a data
contract problem upstream, not a math problem.

### 5.2 Do not hit live API endpoints during testing

- Tests must run fully offline from saved fixtures. A test that performs a real
  network call is a broken test.
- Do not use production API keys for local iteration or debugging. Do not
  dispatch scheduled workflows (`Fast Odds Refresh`, `Bee-Baked-EV-Bot
  Pipeline`, `Fast Player Props`, `ParlayAPI +EV Props`) as a way to "see if the
  fix worked" — each dispatch spends the monthly quota.
- To validate against real data, read the existing Supabase cache
  (`ODDS_REFRESH_ON_MAIN=false`) rather than fetching new odds.
- Never add bulk scans (all sports × all markets) without first computing and
  stating the credit cost.

### 5.3 Other prohibitions

- Do not commit `.env`, `.env.*` (except `.env.example`), or any file containing
  a key, webhook URL, or proxy password.
- Do not log, print, or forward secret values, including into Discord messages.
- Do not lower or disable a throttle, retry cap, or credit cap to make a run
  finish faster.
- Do not disable, skip, or delete a failing test to get CI green.
- Do not reorganize the directory layout or relocate modules.
- Do not push directly to `main`.

---

## 6. Escalate rather than improvise

Stop and ask when any of the following occur:

- A fix would require changing EV math, Kelly sizing, or the Pinnacle baseline.
- A bookmaker begins serving a CAPTCHA or hard-blocking our IP range — that is a
  sourcing decision, not a code fix.
- A required secret or quota is exhausted or missing.
- The change would increase scheduled API spend.
